# 数据、状态与模块契约

## 1. 契约用途

本文是后续`app/src/domain/model.ts`及所有调用方的唯一类型依据。示例是实施规格，本轮不创建代码或占位数据。所有业务内容由人工审核的本地数据提供；不能靠标签相同、证据数量、AI推理或玩家选择生成历史结论。

固定物件顺序与ID：`list`、`map`、`battery`、`shoes`、`bowl`。历史节点、线索、命题、资料、资源均使用稳定ID，不用数组下标作为存档标识。研究台账H/T/A/L编号可在正式Source中保留，同一转载链须登记为同一作品链。

## 2. 内容类型

以下接口须完整落地；TypeScript所有ID字段是字符串，导入的未知值仍需运行时校验。数组和内容对象在运行时不允许修改。

```ts
export type ObjectId = 'list' | 'map' | 'battery' | 'shoes' | 'bowl'
export type Basis = 'history' | 'story' | 'model'
export type Level = 'confirmed' | 'inferred' | 'unknown'
export type View = 'room' | 'case' | 'ending'
export interface Citation { sourceId: string; locator: string }
export interface Source {
  id: string; title: string; url: string; publisher: string
  author: string | null; publishedOn: string | null; accessedOn: string
  workId: string; kind: 'archive' | 'museum' | 'research' | 'report' | 'standard' | 'license'
  usageNote: string
}
export interface Asset {
  id: string; path: string; kind: 'image' | 'audio' | 'font'
  alt: string; creator: string; origin: 'original' | 'licensed' | 'ai-assisted'
  license: string; licenseUrl: string | null; attribution: string
  approved: boolean; reviewNote: string; transcript: string | null
}
export interface HistoryNode {
  id: string; title: string; timeLabel: string; summary: string
  citations: readonly Citation[]; x: number; y: number
}
export interface ObjectView {
  id: string; assetId: string; label: string
  hotspots: readonly { clueId: string; x: number; y: number; radius: number }[]
}
export interface Clue {
  id: string; text: string; basis: 'story'; viewId: string
  requiresPuzzleSolved: boolean
}
export interface DocumentCard {
  id: string; title: string; text: string; basis: Basis
  citations: readonly Citation[]
  requiresArchivedObjects: readonly ObjectId[]
}
export interface Claim {
  id: string; text: string; basis: Basis
  acceptedLevels: readonly Level[]
  requiredClueIds: readonly string[]; requiredDocumentIds: readonly string[]
  explanation: Record<Level, string>; citations: readonly Citation[]
}
export interface CaseFile {
  id: ObjectId; title: string; question: string; fictionNotice: string
  historyNodeIds: readonly string[]; views: readonly ObjectView[]
  clues: readonly Clue[]; documents: readonly DocumentCard[]
  claims: readonly Claim[]; requiredClaimIds: readonly string[]
  takeaway: string; puzzle: PuzzleConfig | null
}
export interface ArchiveContent {
  schemaVersion: 1; contentVersion: string; title: string; introduction: string
  sources: readonly Source[]; assets: readonly Asset[]
  history: readonly HistoryNode[]; cases: readonly CaseFile[]
  ending: { title: string; text: string; reflection: string }
}
```

`Basis`与`Level`必须分开：前者说明事实来自历史资料、原创故事还是教学模型，后者说明该命题在自己的范围内能确认到什么程度。“叙事中的可确认”不能显示成“历史已证实”。历史命题必须有Citation；story没有伪造外部出处；model引用仅解释现代规则，不转成历史依据。

`acceptedLevels`由审核者逐条写定，可有多个合理等级，但不能为空。反馈`explanation`为三种等级各写具体解释，包含资料能说明什么、缺口在哪里；不使用通用“答案错误”。未知物主命题不应存在confirmed。`requiredDocumentIds`所列资料是论证所需，不是“凑两条即可确认”。

跨物件故事关联集中写成饭碗的DocumentCard，text明确引用已建档物件的具体线索ID与记录内容，不能仅凭笔画或纹路相似确认同一人。06规定四张关联资料分别依赖list、map、battery、shoes，最终必需命题`bowl-handover`要求四张资料及碗自身两条线索`bowl-marks`、`bowl-receipt`；确认范围是原创任务的交接结果。前四件的必需命题不得依赖跨物件资料，保证各自可独立建档。饭碗可在任意三件后进入并保留互动进度，第四份前置未齐时明确提示返回调查，不允许提前建档。工作台早期对照只并排展示已发现、已建档的本件记录，不新建全局关系数据库或进度字段。

## 3. 五件互动配置与进度

坐标均为原创示意平面，不是测量值。物件观察与拼合使用0—1000归一坐标，角度为整数度；历史总图与四渡时序作为可选背景阅读资料，不设必需排序关卡。所有容差是交互参数，模型说明必须可见。

## 3.1 小游戏与纯审视物件

五件中仅**名单**（三片拼合、有限清理、辨字）和**饭碗**（双记号拓印）有独立小游戏。行军图、电池盒、草鞋为纯审视物件：玩家转动、翻面、放大物件，发现痕迹并读取随物记录，再在证据板保留判断。三件的`puzzle`为`null`，不使用空配置、隐藏计时或UI成功旗标充当完成条件。

```ts
export interface Point { x: number; y: number }
export interface Pose extends Point { rotation: number }
export interface ListConfig {
  kind: 'list'; pieces: readonly { id: string; target: Pose }[]
  distanceTolerance: number; angleTolerance: number
  cleanCellIds: readonly string[]
  characters: readonly { id: string; candidates: readonly string[]; accepted: string | null }[]
}
export interface BowlConfig {
  kind: 'bowl'; rubbingIds: readonly string[]
}
export type PuzzleConfig = ListConfig | BowlConfig
export interface ListSnapshot {
  kind: 'list'; placements: Record<string, Pose>; cleanedCellIds: string[]
  characters: Record<string, string | null>
}
export interface BowlSnapshot { kind: 'bowl'; rubbingIds: string[] }
export interface PuzzleByObject {
  list: ListSnapshot
  map: null
  battery: null
  shoes: null
  bowl: BowlSnapshot
}
export interface SavedClaim {
  level: Level; clueIds: string[]; documentIds: string[]
}
export interface CaseProgress<K extends ObjectId> {
  foundClueIds: string[]; readDocumentIds: string[]
  savedClaims: Record<string, SavedClaim>
  puzzle: PuzzleByObject[K]; archived: boolean
}
export type ProgressByObject = { [K in ObjectId]: CaseProgress<K> }
```

判定函数`isPuzzleSolved(config, snapshot)`以配置和当前进度计算结果，不接收UI给出的success：

- list：三片分别在容差内；必需清理单元完成；characters中必须显式包含每个待辨字符的ID，值符合accepted。缺少键表示尚未选择，值为null表示用户明确选择保留未知，两者不能混同。
- bowl：`rubbingIds`包含全部必需记号ID。拓印完成不代替`bowl-handover`的证据判断；前四件资料齐备后，可确认故事内的任务已接收，不能升级为真实身份、确切年代或历史生还证明。
- puzzle为null的三件：`isPuzzleSolved`不参与其建档。行军图、电池盒、草鞋的建档只要求必需线索已发现、必需资料已读且必需命题已有效保存，与其他物件同一套证据规则。

名单与饭碗的判定都以配置和当前快照计算，不接收UI给出的success。Canvas清理持久化单元ID，不存像素和每帧轨迹；拼图与拓印有点击/键盘等价操作，快照不记录指针位置。局部观察角度、缩放和光照属于UI临时状态，不进入存档。

## 4. 会话与事件

```ts
export interface Selection {
  claimId: string | null; level: Level | null
  clueIds: string[]; documentIds: string[]
  assessed: boolean
}
export interface Session {
  view: View; activeObjectId: ObjectId | null
  progress: ProgressByObject; selection: Selection
  sourceCitation: Citation | null
  settings: { soundEnabled: boolean; reducedMotion: boolean }
  ending: { selectedObjectId: ObjectId | null; caption: string }
}
export type PuzzleEvent = { [K in 'list' | 'bowl']:
  { type: 'puzzle.update'; objectId: K; snapshot: PuzzleByObject[K] }
}['list' | 'bowl']
export type SessionEvent = PuzzleEvent
  | { type: 'case.open'; objectId: ObjectId }
  | { type: 'room.open' }
  | { type: 'clue.discover'; objectId: ObjectId; clueId: string }
  | { type: 'document.read'; objectId: ObjectId; documentId: string }
  | { type: 'claim.select'; claimId: string }
  | { type: 'evidence.toggle'; group: 'clue' | 'document'; id: string }
  | { type: 'level.select'; level: Level }
  | { type: 'claim.assess' }
  | { type: 'claim.save' }
  | { type: 'claim.remove'; claimId: string }
  | { type: 'case.archive' }
  | { type: 'case.reset'; objectId: ObjectId }
  | { type: 'ending.open' }
  | { type: 'ending.select'; objectId: ObjectId }
  | { type: 'ending.caption'; text: string }
  | { type: 'source.open'; citation: Citation }
  | { type: 'source.close' }
  | { type: 'settings.change'; soundEnabled: boolean; reducedMotion: boolean }
  | { type: 'session.reset' }
```

`createSession(content)`生成初始会话，所有资料/线索/已存命题集合为空，archived=false；名单characters为空对象而不是预填null，其余谜题字段为各自配置下的未完成初值。`applyEvent(session,event,content)`返回更新会话，保持纯函数。`canArchiveCase(content,progress,objectId)`、`isObjectUnlocked(session,objectId)`、`canOpenEnding(session)`、`assessSelection(session,content)`是共享选择器。UI不得复制这些判断，也不把visited当学会。

| 事件 | 必需规则 |
| --- | --- |
| case.open | 只接受已解锁物件；进入case，清空selection和来源弹窗；不丢进度 |
| room.open | 回room，activeObjectId=null，清空临时选择与来源；保留progress |
| clue.discover | 当前物件中的有效线索；需要puzzle solved时先校验；去重，跨物件无效 |
| document.read | 当前物件有效资料且前置物件均已建档；去重；不自动生成线索或保存结论 |
| puzzle.update | 仅名单与饭碗、且当前未建档；类型、ID、坐标与资源限制合法；禁止导入UI的成功旗标 |
| claim.select | 只选当前命题；清空证据、等级与assessed |
| evidence.toggle | 只允许当前已发现线索/已读资料；切换去重，取消旧assessed |
| level.select | 选择三种等级之一；清除旧assessed |
| claim.assess | 命题、等级、证据均合法时assessed=true；反馈由对应命题与选择器派生，不自动保存 |
| claim.save | 必须assessed、选择符合命题acceptedLevels且覆盖required证据；写SavedClaim；不按数量判真 |
| claim.remove | 仅当前未建档物件可移除已有判断；已建档物件拒绝该事件，必须先确认case.reset |
| case.archive | 谜题通过、requiredClaimIds引用的requiredClueIds并集均已发现、所有requiredClaimIds已有效保存；标archived，不要求物主姓名或填写感言。非必需额外线索不作为隐藏门槛 |
| case.reset | 用户确认后重置该件，执行级联回退；不是全局重置 |
| ending.open | 五件archived才进入ending；否则保持当前视图并由UI说明缺少哪件 |
| ending.select/caption | 仅ending可修改；物件有效，caption以Array.from计Unicode字符，超过50不提交，显示具体上限 |
| source.open | 引用必须实际存在于content并能找到Source；只开本地元数据，外链另由用户点击 |
| settings.change | 改两个布尔项，关声音同步停止播放；不改变进度 |
| session.reset | 确认后重置全部会话、settings与caption；平台在新状态成功写入前不能先删除旧备份 |

已建档物件只读回看，拒绝puzzle.update、claim.select、evidence.toggle、level.select、claim.assess、claim.save和claim.remove等编辑事件；已发现线索/已读资料可重复查看但不新增记录。重做须明确确认case.reset，不能边拖动边破坏归档。

**级联回退：**确认重置任何已建档物件后，若饭碗某资料的requiresArchivedObjects不再满足，则移除饭碗该资料的readDocumentIds、临时选择及依赖它的savedClaims；饭碗失去归档条件时取消其archived。前四件少于三件时同时锁饭碗，若正在饭碗则返回room。任何物件未建档时终章退出room，清空ending选择和caption前须由UI在确认提示中说明；不把已解锁永久记录成状态。仅与前置关联的饭碗资料回退，不抹去仍有效的拓印/谜题进度。

## 5. 持久化与数据保护

存储键固定`long-march-lost-found:save:v1`。存档只保存版本、物件进度、两个设置及ending字段；不保存视图、临时选择、Source全文或素材。导入恢复回room，来源关闭，选择清空；终章与解锁从进度重算。

存档包字段为`schemaVersion:1`、`contentVersion`、`savedAt`、`progress`、`settings`、`ending`。schema或content版本不同不静默迁移：保留原值，提示导出旧备份，再由用户选择重开或导入同版本；不创建未经定义的迁移器。

`loadSave(content)`返回`{status:'empty'|'valid'|'invalid'|'unavailable', session:Session|null, message:string|null}`；`saveSession(session,content)`返回`{ok:boolean,message:string|null}`。JSON解析、存储权限、容量不足与导入字段均是信任边界，不能无catch覆盖旧值。

- 拒绝超过256 KiB的导入JSON、未知版本、无效枚举、非有限坐标、越界旋转、重复ID、不存在或未读证据、无效建档状态、未解锁的跨物件资料，以及超过50字的caption。进度须满足合法演进能到达的前置条件，不能信任archived=true。无小游戏物件出现非null的谜题字段同样拒绝。
- 导入先解析到独立对象，校验并提示将替换进度，用户确认后才提交；失败保留当前会话与旧存档。导出JSON可随时手动备份，不上传。
- 用户显式操作结束后写入，最多每300毫秒合并一次；离开视图/页面前尝试提交。清理每个格子的每帧不写存储，设置与建档即时提交。
- 写入失败继续内存体验，明确显示“本次进度暂未保存，请导出备份”；不得声称保存成功。用户输入以文本渲染，不用v-html。
- 不自动清空、重试循环写入或发送诊断；不存真实姓名、学号、电话号码、设备指纹。

## 6. 组件通信契约

所有业务组件以`content`当前片段和`session`只读切片为props，统一emit`event: SessionEvent`；不得直接改props或import应用store。

| 组件 | 必需props | 职责 |
| --- | --- | --- |
| ArchiveRoom | cases、history、progress | 物件入口、派生解锁与路线点亮 |
| ObjectInspector | caseFile、assets、progress | 视角、缩放、侧光、热点与等价列表；发clue.discover |
| ListPuzzle/BowlPuzzle | config对应类型、snapshot对应类型、readonly布尔 | 本地操作后发puzzle.update；不自行宣称完成 |
| EvidenceBoard | caseFile、progress、selection | 命题/证据/等级选择、评估与保留；本地反馈使用共享assessSelection |
| ArchiveReview | caseFile、progress | 真实保存记录、依据范围与重新调查入口 |
| EndingPanel | cases、progress、ending | 选择物件、caption，emit业务事件；导出票据另emit`export-ticket` |
| SourceDialog | source、citation | 本地出处定位，关闭发source.close；合法http/https外链用noopener |

platform仅由App调用。存档导入/导出、票据、音频错误不是SessionEvent里的历史行为，App维护轻量notice状态，不放入领域进度。组件错误不能悄悄生成默认结论。

## 7. 内容校验与最小行为检查

`validateContent(content): readonly string[]`需给出内容路径与具体原因，检查：

1. 五件ID与顺序唯一；puzzle.kind与物件一致，至少一个必需命题，所有引用与资源有效。
2. 历史节点和history命题有定位引文；source URL仅http/https、日期真实、workId记录转载链；story与model标识完整。
3. Clue与热点一一可达，图像有alt；必要线索不能被终章/归档门槛反锁；前四件必需判断可独立完成，饭碗在三件后可进入、最终必需资料依赖全部前四件，四件均不得反向依赖饭碗，保证无循环。
4. Claim三等级反馈非空，acceptedLevels合法，必需证据属于可访问范围；物主身份未知不能以相似痕迹变成confirmed。
5. 两种谜题配置有至少一条合法解法；拼合旋转与容差有上限，`rubbingIds`与热点一致；其余三件`puzzle`为null，其必需命题只引用本件线索与资料。
6. 必需素材approved=true、path本地存在、许可记录完整；音频带字幕；不含外部CDN或数据URI冒充来源。

永久测试覆盖合法/非法事件、跨物件ID、同一证据重复发现、评估后改选不能保存旧反馈、撤销级联、解锁与终章、损坏存档不覆盖、导入前置校验、拼合角度边界、未知字符null与Unicode字数，以及无小游戏物件只按证据规则建档。不要断言固定文案、组件存在或默认字段转抄。完整流程仍须浏览器实操。
