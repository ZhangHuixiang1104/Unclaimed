# 当前分章设计与运行口径

> 2026-10-18 修订。用户明确纠正：“转三”只是**名单的剧情之一**，不能写成整部作品的共同任务，更不能放在注册页和首页提前剧透。本文件优先于此前的五件串联版策划稿；旧稿作为创作过程资料留存，不作为当前实现或素材制作依据。

## 作品定位

玩家先注册／登录档案员账号，再领取五件来源未明的**原创叙事物件**。按名单、行军图、电池盒、草鞋、饭碗的顺序调查，每件有独立的观察问题、候选说法和可确认／可推测／仍未知的边界。顺序解锁是体验节奏，**不是**说五件属于同一主人、同一任务或同一条真实长征路线。

玩家先亲手读出物件的故事，再进入独立的史实材料。名单采用专属三幕故事流程，行军图采用四段改线故事与展签流程；电池盒、草鞋、饭碗目前沿用通用观察、说法筛选与证据判断示意。史实页以独立来源讲述与该件主题相关的真实历史，不能把虚构道具或游戏叙事当作文物出处。已公开的主题在 `/history` 索引可重读，未完成节点保持封存。五件都归档后进入终章，玩家为一件自己选择的物品写展签。

名单章节现有专属流程：三片纸先散放，玩家拖回原位吸附；随后清理正面泥点；再按正面第三行、背面记号图例、背面回执裁口的顺序，直接点击纸面阅读三幕故事。观察工具可选，不再作为解锁条件；名单不使用「添加标记」、五题筛选或盖章。三幕齐备后玩家保存这份**虚构名单**能讲到的故事，再点击“翻阅真实档案”进入独立的 `/history/list` 展柜，四站史实材料读完后才建档。游戏故事与真实手迹只在照护和记录的主题上呼应。其他四件不沿用名单的拼纸、清泥或“转三”设定。

## 具体页面与存档

`/account → / → /archive → /object/list → /history/list → /object/map → /history/map → /object/battery → /object/shoes → /object/bowl → /history → /ending → /ticket`。名单和行军图都须从独立史实入口读完四站并建档，才能开放下一件；已归档章节可在 `/history/:objectKey` 重读史实。后三件暂沿用通用揭露与建档流程。`/about` 是作品说明。首页、账号页和封存页只呈现玩法承诺，不公布章节任务编号或谜底。

前端为 Vue 3／TypeScript／Vite／Pinia，后端为 FastAPI／SQLAlchemy／SQLite。账号使用 HttpOnly Cookie，进度按账号保存；前端开发端口 4173 将 `/api` 代理到后端 8000。**只开前端，注册后的首次云存档就可能失败。**账号已经创建但同步失败时，先启动后端、检查 `/api/v1/health` 返回的 `saveContract` 是否为 `independent-chapters-v3`，再用原账号重试；不要重复注册、删除 `backend/data/archive.db` 或直接覆盖旧档。新进度在云端未确认前会暂存本机，重连按修订号补传；玩家不可把本机暂存当成已完成的云端存档。

当前内容版本标识为 `independent-chapters-v3`。此标识只是防止旧版不同谜题的存档被误当作新版进度，不是游戏标题。旧版有进度的云存档会停在升级页：先下载 JSON 备份，玩家确认后才开启新版。现阶段没有 JSON 导入恢复和服务端历史版本；公开部署前须补数据库备份、HTTPS、Cookie 安全设置与登录限流。
