# 开发优先级与验收

当前仓库已有前后端与完整页面骨架，不再执行“从零创建 app／本地存档／前四件自由”的旧计划。[08当前分章方案](08当前分章设计与运行口径.md)是剧情与创作依据；[01总体架构](01总体架构.md)是实际技术入口。

| 优先级 | 工作 | 可验收标准 |
| --- | --- | --- |
| P0 已实施基础 | 五件独立谜题、顺序解锁、史实/虚构分区、旧档版本保护 | 前端可构建；其他四件不承接名单的“转三”任务；旧版云存档不被自动当作新版通关 |
| P1 进行中 | 名单正式道具图、拼合清泥、土城史实短卡与来源 | 首件不靠提示直接剧透；真实手迹与游戏名单不会被误认为同一件 |
| P2 待做 | 地图／电池盒／草鞋正式视角和各自谜题的专属操作 | 能独立判断墨线先后、维修层次与鞋履磨损，不引入“转三”领用联 |
| P3 待做 | 饭碗拓印与双刻痕比较 | 不将饭碗误写成名单回执；云存档可恢复 |
| P4 待做 | 章节索引双层表达、五个史实页来源、视觉/键盘/音频验收 | 连线明确为调查顺序；锁定史实不剧透；所有正式图可说明权利 |
| P5 待做 | 多人试玩、公开部署安全、说明书和真实演示视频 | 新账号从注册到终章独立走通；后端、账号、素材与视频一致 |

本次文本示意版并不等于正式物件小游戏完成。测试至少覆盖前端 `npm run test`、`npm run build` 和后端 `python -m unittest discover -s backend -p 'test_*.py' -v`；真实浏览器仍须检查 PC 尺寸下的字体、遮挡、正反面、存档刷新、旧档升级及网络失败。不要拿构建通过替代内容、历史来源和美术授权验收。

提交前核对比赛官方要求、截至日期、参赛资格、源码与视频的一致性。任何新增历史事实或资产都先补来源及使用权记录，不以游戏内部推理取代历史核验。
