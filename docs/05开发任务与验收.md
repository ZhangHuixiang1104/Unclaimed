# 开发任务、质量门槛与交付验收

## 1. 使用方式与当前边界

当前已决定开发《长征失物招领处》，完整范围是五件可调查、可建档的物品与终章。本轮完成的是准备材料；以下任务均为后续应用开发要求，不表示已经实现、运行或验收。

实施前读[总体架构](01总体架构.md)、[数据契约](02数据与状态契约.md)、[交互视觉](03交互与视觉.md)、[内容素材规范](04内容与素材规范.md)、[游戏剧情流程](06游戏剧情流程.md)和[比赛要求](比赛要求.md)。06包含完整谜底，按玩家调查进度投放，不能整篇作为入场介绍。研究记录在research，参考原方案与archive不覆盖当前契约。

“大厂规范”在本项目体现为明确责任、可追溯内容、单一契约、可重复运行、行为验证和交付证据。按照实际三人团队执行，不建立虚拟组织层级、微服务或通用插件平台。

## 2. 实施阶段与门槛

| 阶段 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 内容定稿与技术初始化 | 五件事实/叙事/模型清单、首件正式素材；Vue/TS基础环境及02类型 | 核心史实范围与许可清楚；实际包版本兼容并锁定；脚手架演示内容删除 |
| 首件闭环 | 名单拼合、辨字、任务栏与回执缺口；本地恢复与来源 | 正式可读素材；请3人试用，至少2人理解要查什么及虚构/史实区别；状态与存储边界通过 |
| 扩展五件 | 改点分批、器材领料、草鞋照应、饭碗回执及跨物件回退 | 各件可调查、证据可核对；前四独立建档，饭碗完整关联无循环，谜题有解 |
| 整体体验 | 任务结果回看、五件解锁、PNG票据、声音/字幕、移动端与键盘 | 真实浏览器走通推荐顺序及自由顺序，饭碗第四件先开、重置/导入/断网场景实测 |
| 功能冻结与提交准备 | dist、源码、说明书、依赖/运行说明、2—3分钟实录、授权与来源 | 独立环境按说明运行，源码/视频一致，提交清单全齐 |

名单先行是内容与状态验证顺序，电池盒仍是视频中的技术重点。若首次试玩失败，修改问题、反馈或视觉，不用增加奖励掩盖不理解。原型不代表整个产品交付；不能因原方案“至少四件”而省去第五件或卡住终章。

比赛截止2026年11月5日23:00。建议10月18日前验收首件、10月25日前贯通五件、10月30日前完成试玩修正、11月3日冻结、11月4日录屏；这些是检查点，不是已测工期。先记录每人的实际可投入时间和首件耗时，再估剩余任务。时间紧时优先减少装饰、配音数量与联网统计，不删核心范围或伪造完成。

## 3. 模块责任与变更制度

| 责任 | 拥有文件/内容 | 不可擅改的共享部分 |
| --- | --- | --- |
| 集成负责人 | App、main、domain类型/会话/选择器、platform、依赖配置、全局tokens、质量脚本、最终发布说明 | 改02时须同步所有调用方与文档，不能只改自己的模块 |
| 内容与视觉负责人 | content、原创素材、来源与资产登记、命题/反馈及审核记录 | 不改会话、算法或依赖，不用虚假史料配合界面 |
| 互动开发负责人 | 名单与饭碗纯算法及对应Puzzle组件，观察台、审视交互和证据组件按约定分配 | 不另建store、不直接改App/存档，不自行重新定义同名类型 |

人数少时合并职责；并行工作前写清文件所有者、共享契约版本与输入输出。最多同时运行两个实现子任务，同一文件由唯一所有者集成。缺少正式素材时先推进纯逻辑与资料，不把假物件或假历史文本作为正式UI验收。

每个变更围绕用户问题写明：结果、影响文件、依据、实际检查与限制。契约改动先列出组件、内容、存档与测试受影响面；新内容版本触及存档时按02拒绝不兼容旧存档并保留导出，不静默迁移。提交主题可用feat/fix/docs/test/chore，不以提交数量衡量进度。

## 4. 可直接执行的任务书

### A：初始化、状态与集成

1. 在app创建Vue 3＋TypeScript＋Vite项目，复核本机环境和依赖要求，提交锁文件；不安装全局工具、不改用户环境。
2. 逐字落实02的model，内容初始对象只写真实已审核数据；建立createSession、applyEvent与共享选择器。
3. 实现五件解锁、命题评估/保存、单件重做的级联、全局重置、来源与终章。展示状态由进度派生，不重复存completedCount或unlockedEnding。
4. 实现有版本本地存档、损坏/禁用/满额反馈、手动JSON导出和确认后导入；未核验的数据不覆盖现有存档。
5. 实现本地音频/字幕、PNG票据；Canvas失败和字体/图像未就绪有真实反馈，保留用户文字。
6. 集成全部组件，统一导航、弹窗、notice、焦点和错误提示，组织正式检查与浏览器验收。
7. 更新根README的实际命令、环境、部署路径及验证结果；补开发说明和变更记录，记录自主开发与第三方/AI使用。

完成标准：不是“能编译”，而是五件、来源、重置、存档、终章和票据均在真实浏览器可完成。

### B：内容、原创素材与证据审核

1. 从H/T研究记录建立Sources，保留workId与locator。核关键日期、部队主体和器材范围；待查点不写成已确认。
2. 按06写五件CaseFile、HistoryNode、DocumentCard与Claim，标记、任务编号与辅助记录实际可见，basis始终明确；三等级反馈人工审核，不以证据数量定真。
3. 本件必需判断围绕任务推进，不机械重复物主未知。缺字显式选择null，真实姓名/确切日期地点缺证时保留未知，故事内交接结果则须有明确证据与结论。
4. 依据04制作原创图像与配音，登记作者、源稿、许可、AI辅助和实际检查；approved只有在权利/内容/文件三项通过后为true。
5. 饭碗四份关联资料各依赖一个前置物件，最终判断必须核齐；前四件不得反向依赖饭碗；工作台只显示已建档且已发现的记录。小游戏完成不代替证据判断。
6. 请另一名成员复核关键事实与命题；提交不确定性、取舍说明与未授权资产清单，不能填虚构复核人。

完成标准：五件都有可发布的内容与素材，所有正式引用可定位；来源全文不打包进产品，素材许可与历史依据分列。

### C：互动与组件

1. 按02实现ListConfig/BowlConfig与纯判定，不让UI传success；算法不读取DOM或浏览器存储。
2. 名单完成三片拼合、有限网格清理与辨字未知；饭碗完成双记号拓印。
3. 行军图、电池盒、草鞋为纯审视物件：靠放大、翻面、展开与并排对照发现痕迹、读取记录，再进入证据板；`puzzle`为null，不造空配置或成功旗标，也不要求通信、步伐或修补练习。
4. 全流程无强制反应时间与隐藏计时；每件可只用点击/键盘完成。
5. 组件接受只读props、emit统一事件；所有拖动都有按钮/键盘替代；只把指针、光照和缩放留本地。
6. 提交有解配置和边界检查；图片/音频失败不能输出假完成。与A共同实际走一遍组件到状态的闭环。

完成标准：每件均能用键盘和指针完成，重做不污染其他有效进度，源码与录屏都是真实运行。

## 5. 工程质量门槛与自动检查

后续package scripts采用下列名称，根README只在实现并运行后写具体命令结果。本轮没有package.json或可执行这些命令的应用。

| 名称 | 执行内容 |
| --- | --- |
| dev | Vite开发服务 |
| typecheck | vue-tsc --noEmit，不能用Vite转译替代 |
| test | Vitest run；包含正式content的validateContent和必要行为测试 |
| check | typecheck与test依次成功 |
| build | check成功后执行vite build |
| preview | 本地检查dist，非生产服务器 |

如后续接入远端仓库，CI在PR上执行锁定环境下的npm ci、npm run build；保存失败日志与构建产物，部署单独触发。当前没有远端仓库，也不提前创建指向假仓库的CI或自动发布工作流。首次锁定依赖后README与CI环境必须一致，不写“latest即可”。

永久测试覆盖消费者可见边界：无效/跨物件ID、重复发现、改选清除评估、未知字符与未填的区别、证据范围、解锁和回退、损坏存档不覆盖、导入限制、无小游戏物件的谜题字段、拼图角度环绕与50字符上限。纯转抄、固定文案、组件存在和mock回声不写成测试。各模块开发时不并发跑全仓构建/格式化；集成后统一执行，失败针对真实原因修正。

## 7. 试玩与内容验证

首件请3人试用，至少2人能说明调查目标、原创与史实的区别，并解释一项判断的依据。完整五件后至少请5名未参与者试玩，记录总耗时、卡点、线索发现顺序与是否误认文物；请其复述接应为何改点、补料去了哪里、交接是否完成及凭什么判断。若只能背主题词或只记住“姓名未知”，先修线索与反馈，不算剧情验收通过。

12—15分钟是体验目标，实测超时先检查重复操作、文本和导航，不能隐藏某件或将答题自动完成；如需减少完整范围，交由用户明确决定。内容误导比动画不够流畅更优先修复。试玩反馈不收集真实身份，说明与感言不自动上传。

来源表、素材许可、署名、AI用途与自主开发内容随包提供；README记录实际运行过的命令与浏览器范围，变更记录记录完成版本。使用用户可确认的真实运行画面录2—3分钟，重点展示物件审视、痕迹与记录比对、证据边界与终章，不能剪出未实现效果。
