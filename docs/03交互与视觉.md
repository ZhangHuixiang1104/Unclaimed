# 交互与视觉规格

## 1. 设计方向与自检

主题是“玩家从物件痕迹还原一项长征途中照应任务”。视觉主角为物件局部、特殊标记和可读证据，采用冷灰档案工作台与靛色笔迹。首页直接呈现调查目标和五个物件，不设现代主角的校园序幕或宣传海报式长首页。

第一轮设计曾考虑暗色拟真档案室与大量做旧纹理；它会遮蔽文字、增加美术量，也容易像密室游戏。修订为明亮检查台＋低亮度外围，物件保持材料质感，文字区域平整清晰。只在物件视角、侧光与维修层体现主题，不把所有区域切成相同卡片，不用自动入场动画制造氛围。

本轮仅制定规格，尚未生成或验证真实页面、截图、颜色对比度与字体加载表现。

## 2. 视觉变量

| 变量 | 建议值 | 用途 |
| --- | --- | --- |
| workspace | #E6EBEE | 主阅读与检查环境，偏冷灰 |
| surface | #F7F9FA | 平整文字区和来源弹窗 |
| ink | #20323F | 正文与关键轮廓 |
| accent | #385678 | 当前操作、焦点和路线强调 |
| confirmed | #245D4C | 可确认状态，必须同时显示文字 |
| inferred | #79571F | 推测状态，必须同时显示文字 |

未知状态用ink的次级层级、虚线标记和“仍未知”，不把它做成红色错误。原始资料、叙事线索和教学模型分别有文字标识，不能只靠颜色区分。边框、禁用态与错误态须在实现时检查对比度，普通文字至少4.5:1、焦点与控件边界至少3:1。

标题可用原版思源宋体，正文与控件用思源黑体；本地字体文件需按研究台账L05/L06保存许可。未经下载核验时使用系统中文字体回退，不引用外部CDN，不为了视觉要求强制在线。标题30/24px、段落16px、标签14px，正文行高1.65，单段控制在约45个汉字宽度以内。桌面最大内容宽度1280px，手机正文不小于16px。

## 3. 页面结构与导航

仅三个主视图：档案室、物件调查、终章。来源与设置用弹窗，不增加独立路由。顶部保留标题、返回档案室、声音与来源说明；进度显示“已建档N/5”，不显示思想分数或“已掌握”。

桌面调查布局：左侧大观察台，右侧当前问题与证据；下方为物件专属互动和建档记录。每件只设一个主要动作：名单为拼合清理，饭碗为拓印，其余三件为审视比对。手机先显示问题和观察台，再显示互动、证据与记录，用同页锚点跳转，不把关键按钮固定压在画面上。

```text
项目标题       返回档案室   声音   来源/虚构说明
当前物件问题                           已建档 N/5
物件观察台（视角/细节）    线索与资料列表
专属互动                  当前命题与三种等级
状态/下一步               具体解释与保留依据
```

档案室五个入口按名单、地图、电池盒、草鞋、饭碗固定排序。前四件可自由打开；饭碗锁定时明确写“先完成任意三件建档”，开放后最终判断尚缺资料则列出对应物件。工作台并排展示已建档物件中已发现的线索与本件判断，支持回到原观察位置，不自动连出任务答案。路线总图依据建档点亮历史背景节点，不声称五件走过同一条真实路线；故事接应小示意与历史总图分开。

## 4. 统一观察与证据流程

### 4.1 观察台

每件至少有正面、背面、关键局部，可用“正面/背面/细节”按钮和拖动两种方式切换。放大/缩小/复位为按钮，滚轮和双指缩放是补充；缩放不改变线索内容。侧光提供少量明确档位，而不是自由复杂照明。

所有热区同步列为可聚焦文字按钮，描述可见痕迹，发现后标“已记录”。清理、拓印或拼合后才开放的线索按02前置条件显示，不能把未找到的文字直接写进默认记录。视图切换不丢进度，光照和缩放局部重置可接受。

进入每件时常显：“本物件为原创数字叙事示意，真实历史背景见史料卡。”不要只在片尾放一次声明。

### 4.2 证据板

分为“叙事线索”“资料与模型说明”“正在判断的结论”。用户选择命题，选择自己查看的证据，再标记等级并展开解释。三等级的可见名称为“可确认”“可推测”“仍未知”，旁边持续显示basis对应的“故事内判断/历史背景判断/教学模型判断”。

评估不自动保存。解释给出支持范围与缺口；选择改变后移除旧评估，已保留记录仍可查看。用户完成本件全部必需命题及互动后，“完成建档”可用；禁用时列出缺少的步骤，不靠挨个试错寻找按钮。

| 状态 | 反馈与操作 |
| --- | --- |
| 尚未选命题 | 提示先选择要核验的结论，证据和等级可读但评估禁用 |
| 命题已选但证据/等级未齐 | 说明缺少哪项；不能用已发现总数替代所需证据 |
| 已评估，范围一致 | 显示具体解释，“保留这条判断”可用，不奖励证据条数 |
| 已评估，需要修正 | 说明为何超出或低于支持范围，允许改等级或查看资料，不写答题错误/战果失败 |
| 选择为仍未知且符合依据 | 正常保留，明确未知不是调查失败 |
| 本件已建档 | 只读记录与依据；“重新调查”须确认回退影响后重置该件 |

来源按钮位于选择控件外，打开来源不误改当前选择。来源弹窗用本地标题、作者/发布方、日期、原载链、定位与使用边界；“打开原文”才离开本地，外网不可用不影响核心体验。

## 5. 五件互动规格

### 5.1 名单

三块纸片可拖动旋转，吸附只提示接近，不替用户补齐文字。等价操作为选中纸片后用方向键移动、旋转按钮调角度，并提供目标区域选择；任何设备都能完成拼合。

泥点清理采用有限网格遮罩：刷过有效单元后记录对应ID，点击单元亦可清理；没有永久损坏或必须抢时间的操作。未准备好正式图像时不以随机文字模拟历史笔迹。

辨字列出候选字与“保留未知”，未知是显式选项，不与尚未选择混同。名单为原创转送记录，拼合后能看到任务栏、状态图例、回执说明与裁口；残缺姓名不自动补全，不用真实烈士姓名编造私史。目标是识别待接任务及另存回执，不将空栏解释为牺牲名单。

### 5.2 行军图

行军图正面为原创示意平面，四渡阶段各有来源与时间口径，作为可选背景阅读：玩家可用阶段按钮或时间滑块查看路线与摘要，均读取同一阶段数据。不要把最短路径当作历史决策基准，示意坐标不计算真实距离和行军速度；四渡底图与时序按历史来源绘制，不称本图为1935年军用原图。这里不设必需图层对齐或排序关卡。

背面/局部视图展示原创接应小示意，是本件调查主体。折叠的小纸纸边露出“转三”和打叉圈点，展开后可见改点箭头、图例、两处旁注与下方分批记录。玩家用放大、翻面、展开和并排对照查看；无箭头的短引线把旁注连到对应位置，共同括线说明两批同去改后接应处。旧点、改点与前后批旁注独立于真实四渡路线，不能叠加成某次真实军事命令；玩家保存的是故事内改点与分批记录。

### 5.3 电池盒

观察盒体和布条时标“原创器材示意”，真实电池型号、容量、材质或部队位置未知时不画铭牌。玩家翻看固定带的新旧接头与备用背带的齐整末端，放大比较磨损边缘和裁切边缘；痕迹只引出材料去向的问题。

盒内折纸展开后显示两组各有栏题的记录：上半部为器材交接，下半部为修补用料领出联。玩家直接读取文字，与接头及已有线索核对；未读记录不出现在默认记录里。本件不设接线、组网、故障重连或短长发送练习，也不需要通信模型即可建档。前批器材已交、备用背带裁口与领出联是物件线索；具体补履用途由草鞋的领用联揭示。

### 5.4 草鞋

通过局部图显示两只鞋的不同尺寸、旧补料与磨损区域，磨损高亮是创作表达，不根据热区诊断真实身份或负重。玩家翻到鞋底观察带状补料跨过断口的位置，展开鞋侧折起的小票读取领用联，再翻面查看照应安排。本件不设材料修补练习或双人步伐测试，调查由补料、领用联与两联对照完成。

旧补料旁的小票显示第三项任务编号、备用背带领料与补履记录，另有留组照应说明；玩家可在故事内确认记录的安排。与盒内记录的最终关联在饭碗核对，不能只因材料相似或尺寸不同，就确认换鞋者、两名物主或最终到达。

### 5.5 饭碗

拓印碗底待接与完成两处记号，指针擦过或“拓印这一处”按钮均可。碗外回执用翻面/展开局部视图查看，不另加拆包关卡。借碗记说明两只记号分别用于待接与接讫；记号本身不承担年代或物主判断，也不需要排序。

编号、交讫内容、名单裁口与回执说明共同支持关联，不能只凭相似笔画作身份证明。饭碗在任意三件建档后可做互动；最终命题按02依赖前四件的四张关联资料，缺一件就提示返回该件并保留碗进度。全部核对后可确认故事内交接结果，不以其他年代地域的馆藏碗冒充长征原物。

前置物件重置时按02撤销受影响的饭碗资料、判断与建档，UI确认中说清影响；仍有效的拓印保留。

## 6. 终章、票据与存档

五件建档后，终章先回看玩家已保存的“待接—改点分批—领料补鞋—照应后随—接收交讫”及对应物件依据，再进入陈列选择。回看由有效进度派生，不新增排序关卡或临结尾才出现的证据；原名单与另存回执并列，不涂改原始记录。事件有明确的故事内结论，姓名与此后经历可未知，不用统一感言替代谜底。

选择一件想保存的物件、填写最多50个Unicode字符的说明。输入区留空，仅提示“你希望下一位观看者注意到什么？”，不展示范文、不预填感言、不指定首选物件。感言可留空，不影响结束；超限提示剩余空间，不静默截断。票据包含作品名、“原创数字叙事作品”、所选物件、五件建档状态与用户文字，不添加统一感言或在用户文字后追加作者结语，不写“真实文物证书”。纪念编号固定显示“2026”，是作品年份标识，不是唯一会话ID、全网排名或官方馆藏号，无需另建编号服务或存档字段。

PNG导出只在五件已建档且已选择一个有效物件时可用，感言可空。由本地素材与文本绘制，先等待字体/图像就绪再输出；若浏览器失败，显示具体错误并保留输入，不假装下载成功。文件名用固定安全名，不直接用用户感言。

设置中提供存档导出、导入与重置。导入和单件重做均先说明会替换哪些数据，再确认；写存档失败时显示持久提示与导出入口。外部链接暂时不可达、音频加载失败、图片加载失败都有明确状态；必要图像缺失属于不可交付问题，不能用空白完成态掩盖。

## 7. 无障碍、响应式与反馈

- 所有核心操作可用鼠标、触屏与键盘完成，拖动/长按都须有点击替代；无按钮仅以图标表达意思。
- 单选/复选使用原生控件，标签与错误提示关联；操作反馈用status区，不把每次缩放播报成洪流。
- 弹窗使用原生dialog或等价完整模态：标题、Escape、焦点约束、关闭后回触发控件；不同时开多个来源窗。
- 焦点边框清晰；触控目标至少44px。不能仅以红绿、音效、视差或运动表达答案。
- 无自动声音，首次用户明确开启后播放；切换物件停止前一段。字幕独立可读，录音不自动推进进度。
- 尊重系统prefers-reduced-motion，并提供本地设置；隐藏页暂停声音与非必要动画，不在后台刷Canvas。
- 窄屏顺序与DOM阅读顺序一致，不用CSS视觉重排打乱键盘导航；200%放大仍可完成。

## 8. 实测与演示要求

以下为后续实际浏览器检查，不是本轮已完成结果：1440×900桌面、390×844手机布局、200%缩放、键盘全过程、减弱动效、断外网本地运行、存档失败和损坏导入。逐件检查观察、互动、证据、建档；重做前三件之一检查饭碗与终章回退。

2分30秒展示建议：前20秒直接展示玩家目标与虚构说明；20—60秒展示名单拼合、状态图例及回执缺口；60—110秒展示电池盒与草鞋的痕迹审视和两联对照，并说明记录只作故事内判断；110—135秒展示物件关联与历史来源的区分；135—150秒展示交接结果回看与玩家票据。其余物件在应用里必须完整可用，不能以预制效果或剪接假点击替代程序。
