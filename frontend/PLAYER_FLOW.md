# 当前玩家流程与页面跳转

首次访问：`/account` 注册或登录 → `/` 首页 → `/archive` 档案室。已有有效会话可直接进入。若云端保存失败，账号仍保留；先确认后端 `127.0.0.1:8000` 运行，再点“重新连接存档服务”。不要因报错重复注册或删除数据库。旧版有进度的云存档须先下载备份，确认后才开始当前内容版本。

## 五件各自独立的故事

| 顺序 | 路径 | 本章谜题 | 归档后开放的史实主题 |
| --- | --- | --- | --- |
| 01 | `/object/list` | “转三”是哪项转送记录？开口框与缺失姓名能证明到哪一步？ | 土城战役后的伤员救护 |
| 02 | `/object/map` | 沟口、北滩、下滩到高地，四次改线回应了什么消息？为何最后停在河前？ | 从四渡赤水到金沙江 |
| 03 | `/object/battery` | 三层布条和接线端说明了什么？数字刻痕是否有已知含义？ | 长征中的通信保障 |
| 04 | `/object/shoes` | 两只草鞋是否真是一双？磨损能否指认使用者？ | 行军生活 |
| 05 | `/object/bowl` | 双刻痕与多次修补意味着什么？能否确定主人？ | 日常供给与互助 |

五件按顺序解锁，**不是同一项“转三”任务的五份证据**。“转三”只在名单章节出现；其他章节不负责补出名单回执或人员结局。首页、账号页、封存节点和未揭露的史实页不提前公布任何章节谜底。

名单流程：三片拖动吸附或 Tab 聚焦后按 Enter／Space 对齐 → 选择轻拭后拖动擦泥或用清理按钮 → 正面第三行、背面图例、回执裁口依序阅读三幕 → 保存虚构故事 → 独立进入 `/history/list` 浏览四站史实 → 建档。故事卡接收键盘焦点，Escape 关闭后返回入口。行军图流程：展开 → 点击正面四处笔迹发现线索 → 阅读背面更新语核对，背注不代替正面线索 → 选择展签并保存 → 独立进入 `/history/map` 浏览四站史实 → 建档后开放电池盒。

`/history` 的折线表示调查顺序。五章都在保存故事并主动揭露史实后，进入各自四站展柜；“已浏览”记录材料访问，归档后可重读。五件归档并获云端确认后开放 `/ending` 与 `/ticket`。终章物件与留言配对保存，回档案室浏览其他物件不改写票据。作品说明在 `/about`。

五章均已接入专属道具与故事流程。当前研究照片已经接入前端构建，发布前仍须逐件核权、核对馆方名称与释文并完成史实终审。本轮保留现有图片和剧情。云端进度存于 SQLite；未上传进度按账号和页面实例分别暂存，冲突期间继续保护新操作。会话失效或共享 Cookie 切换账号时返回原账号登录入口；刷新后发现草稿时复用现有冲突选择页核对。详见[数据契约](../docs/02数据与状态契约.md)及[验收记录](../docs/05开发任务与验收.md)。
