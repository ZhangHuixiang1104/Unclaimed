# 当前玩家流程与页面跳转

首次访问：`/account` 注册或登录 → `/` 首页 → `/archive` 档案室。已有有效会话可直接进入。若云端保存失败，账号仍保留；先确认后端 `127.0.0.1:8000` 运行，再点“重新连接存档服务”。不要因报错重复注册或删除数据库。旧版有进度的云存档须先下载备份，确认后才开始当前内容版本。

## 五件各自独立的故事

| 顺序 | 路径 | 本章谜题 | 归档后开放的史实主题 |
| --- | --- | --- | --- |
| 01 | `/object/list` | “转三”是哪项转送记录？开口框与缺失姓名能证明到哪一步？ | 土城战役后的伤员救护 |
| 02 | `/object/map` | 沟口、北滩、下滩到高地，四次改线回应了什么消息？为何最后停在河前？ | 从四渡赤水到金沙江 |
| 03 | `/object/battery` | 三层布条和接线端说明了什么？数字刻痕是否有已知含义？ | 长征中的通信保障 |
| 04 | `/object/shoes` | 两只草鞋是否真是一双？磨损能否指认使用者？ | 行军生活 |
| 05 | `/object/bowl` | 双刻痕与多次修补意味着什么？能否确定主人？ | 日常供给与互助 |

五件按顺序解锁，**不是同一项“转三”任务的五份证据**。“转三”只在名单章节出现；其他章节不负责补出名单回执或人员结局。首页、账号页、封存节点和未揭露的史实页不提前公布任何章节谜底。

名单的流程是：拖动三片纸吸附 → 正面擦泥 → 点击第三行读第一幕 → 翻面点击记号图例读第二幕 → 点击回执裁口读第三幕 → 回看并保存虚构故事 → 点击「翻阅真实档案」进入 `/history/list` → 逐件翻阅四站真实史料 → 在史实页建档。行军图的流程是：展开横图 → 自行点击正反面笔迹找到四段故事 → 用侧光、逐层透视和描图尺比较 → 翻背读更新语 → 选择有证据支持的展签并保存 → 独立进入 `/history/map` 阅读四站史实 → 建档后开放电池盒。两章各自独立，下一件只在本件建档后开放。

`/history` 的折线只表示**调查顺序**，不是长征地理路线图。名单和行军图保存各自虚构故事并主动揭露后，分别进入 `/history/list`、`/history/map` 完成四站史实阅读和建档；已归档后可反复进入。其余三件暂沿用归档后开放独立史实页的逻辑；未完成节点封存。五件都归档后开放 `/ending` 与 `/ticket`。作品说明在 `/about`。

名单与行军图均已接入独立纸面素材、故事卡、虚构／史实分界和四站史实展柜。行军图史实页在开场时间主轴、每站核心句和每站三段可点开的史实经过中分层呈现历史；四条游戏线索及史实阅读状态已通过前端状态测试、后端存档及重新登录恢复测试。名单与行军图的史实研究照片仅在 Vite 本地开发服务下预览，正式构建不打包这些待授权图片；行军图正式版使用原创后制示意与材料卡。发布前须逐件核权、核对馆方名称与释文，并完成史实终审。两章尚需完整PC浏览器试玩；电池盒、草鞋、饭碗仍以通用示意为主。云进度登录后存入后端 SQLite；只有尚未上传的游戏进度临时留在当前浏览器，重连补传后清除，不含密码。参见[行军图专题入口](../stuffs/行军图/README.md)、[名单制作稿](../stuffs/名单/名单前端制作坐标与SVG方案.md)、[设计系统](DESIGN_SYSTEM.md)和[当前内容口径](../docs/08当前分章设计与运行口径.md)。
