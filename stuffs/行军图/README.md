## 一句话讲清本章

一张**虚构的无名河谷行路小图**被改出四层线：前两次试图找到通道，第三次转向另一处水边，最后一条线却**止于等候高地，不越过河**。玩家查明每次改线所回应的新消息，理解“停下等待核实”也是一次负责任的行路决定；但图上没有全队最终渡河的记录。

独立史实展柜按“**四渡赤水后的转向 → 云南军用地图 → 金沙江多个渡口的尝试与改道 → 皎平渡的船与船工**”展开。游戏小图既不是四渡赤水路线，也不是1935年缴获的云南军用地图，图上的无名河谷、笔迹和报信均为原创叙事。

## 已锁定的跨文件口径

1. 调查顺序仍是名单 → **行军图** → 电池盒 → 草鞋 → 饭碗；这不是五件物品共主、共任务或真实行军时间线。行军图不续写名单的“回执另存”，也不出现“转三”。
2. 游戏四条线是**一张小图的四次版本**，不是历史上四渡赤水的四次渡河；红色线不等于红军历史路线。无名河谷的方位、折线、等待高地均不得套到真实地名上。
3. 游戏结论只到“为什么暂停、纸上记载了什么、仍未记载什么”。“最后安全过江”“全队抵达”不能从图上推出。
4. 真实路线与图版在独立的 `/history/map` 展柜出现，先明确切换到史实，再按资料级别标注“文献／采访报道／后出的示意图／纪念地今景”。
5. `map` 已从通用检查台切换到独立故事流程：展开、翻面、侧光、分层、描图、四张隐藏故事卡、展签、史实四站与建档。账号存档仍由现有云端服务负责；旧通用行军图线索会只重开本章，保留其他章节进度。

## 建议制作顺序

当前构建和自动化验证已通过：前端 `npm run build`、`npm test`（19项），后端 `python -m unittest discover -s backend -p test_app.py -v`（7项）。后端存档合同已容纳4条行军图线索，并测试退出后重新登录恢复；后续仍需真人PC试玩、史实终审与生产环境账号联调。
