# 「名单」前端精确制作稿：文字、坐标、SVG 与素材叠层

> 状态（2026-10-18）：本稿记录当前 PC 可运行版与待验收项。实现见 [`ListArtifact.vue`](../../frontend/src/components/investigation/ListArtifact.vue)、[`ObjectInspector.vue`](../../frontend/src/components/investigation/ObjectInspector.vue)、[`ListStoryNotebook.vue`](../../frontend/src/components/investigation/ListStoryNotebook.vue) 与 [`ListStorySynthesis.vue`](../../frontend/src/components/investigation/ListStorySynthesis.vue)。三片初始散放并可拖动吸附；清泥后直接点击纸面三处具体记录，逐幕阅读故事卡，保存故事后才出现独立史实入口。名单不再使用「添加标记＋五题筛选＋盖章」流程；视觉与真实浏览器操作仍待逐项验收。

## 1. 坐标和素材基准

- 所有下文的 `x / y` 都相对 **1448 × 1086** 的完整纸面 SVG `viewBox`，原点在左上，**不是浏览器像素**。正反面母版也正好是 1448 × 1086。纸张可见外沿约为 `x=76–1373, y=75–1011`。
- 组件在检查台中央按 4:3 等比缩放，目标宽度 `min(舞台宽度×74%, 610px, 视口高度×68%)`；页面变化时文字、切口、泥点和纸纹共同缩放，不各自重排。
- 背面材质图先水平镜像以对应同一张纸的折痕；背面手写字透明 PNG 和记号**不镜像**，按纸面坐标正向绘制。
- 纸张外缘和三片切口使用同一 SVG 几何约束正背面。生成图天然外沿仍有几像素差异，不能用两张 PNG 各自的 alpha 边界计算拼合。

| 层级（由下到上） | 内容 | 当前素材／实现 | 边界 |
| --- | --- | --- | --- |
| 0 | 检查台环境 | `list_desk_bg.png` | 只作背景；按钮、故事手账仍是 HTML |
| 1 | 三片纸面 | `list_front_master_blank.png` / `list_back_master_blank.png` + SVG `clipPath` | 正背共用三条片形，不随机生成破边 |
| 2 | 纸纤维侧光 | `list_raking_light_texture.png` + 随鼠标移动的径向 SVG 蒙版，透明度 `.13` | 只是质感，绝不生成答案笔迹 |
| 3 | 中文手迹、分隔线、记号 | 14 张经人工校字的透明手写 PNG；分隔线、方框和圆点使用 SVG | 文字与底纸分层，不能由生成图直接假写；200% 放大仍须实机检视 |
| 4 | 泥点 | `list_mud_overlay.png` 绘到 Canvas | 只遮正面「备用物料」的「料」，不影响纸张或其他字 |
| 5 | 工具提示、故事触点、手账反馈 | 名单专属检查台 UI | 不预先给谜底编号；纸面点击直接弹故事卡 |

## 2. 正面手写图层坐标稿

正面墨色约 `#40382D`。下表的 `x, y` 是手写 PNG **可见墨迹包围框的左上角**，并非透明画布左上角或文字基线。`ListArtifact.vue` 的 `placeInk()` 按各 PNG 的 alpha 边界换算。下一轮如调整排版，应同步核对泥点位置、实缺和线索触发区域。

| 可见内容 | 可见墨迹起点与高度／几何 | 说明 |
| --- | --- | --- |
| `转送事项` | `(260, 180)`，高 `72` | 只属于这件虚构游戏道具，不上登录页／首页 |
| 标题下分隔线 | `M257 292 H1158` | 细墨线，代码绘制 |
| `转一` ／ `器材` | `(260, 365)` ／ `(480, 365)`，高 `48` | 右侧框内加点 |
| `转二` ／ `备用物料` | `(260, 490)` ／ `(480, 490)`，高 `48` | 仅末字「料」被泥点暂时盖住 |
| `转三` ／ `后随二人` | `(260, 630)` ／ `(480, 630)`，高 `48` | 右侧开口框，不能改成完成记号 |
| `姓名` | `(260, 826)`，高 `48` | 姓名值**不绘制任何字**，由纸张实缺占位 |
| 姓名栏虚线 | `M457 879 H800` | 被物理缺口一并裁断，不能跨缺口悬浮 |

三个记号全部由矢量绘制，尺寸一致，避免 Unicode 方框在不同电脑上变形：

```svg
<!-- 转一：框内加点；转二同形，整体下移 125 -->
<rect x="1095" y="360" width="54" height="54" />
<circle cx="1122" cy="387" r="6" />
<rect x="1095" y="485" width="54" height="54" />
<circle cx="1122" cy="512" r="6" />
<!-- 转三：上边中央故意留 21 单位开口 -->
<path d="M1095 625 H1112 M1133 625 H1149 V679 H1095 V625" />
```

不要在纸上真的印 `〔缺失〕`、准确认领人名、完成章或史实人物姓名。那是制作标注，不是玩家能读到的纸面内容。

## 4. 三片 SVG、断口和实缺

三个 `clipPath` 均在完整纸面坐标内定义，正反面完全复用，交界处故意留细缝。初始位移：左片 `(-65,+24)`、右上片 `(+70,-53)`、右下片 `(+60,+52)`；即使完整纸张轮廓作为虚线参考，三片仍与目标位置明显错开。玩家在正面拖动单片，释放时位移距离目标 `≤45` 个 SVG 单位自动吸附到 `(0,0)`。三片都吸附才记 `list-pieces-assembled`；拼合状态存云端，不保存每次拖动轨迹。拼好后可以翻面，翻面不会更换片形。

```svg
<clipPath id="list-piece-left" clipPathUnits="userSpaceOnUse">
  <path d="M0 0 H721 L711 185 L725 340 L716 470 L742 548 L701 676 L684 842 L696 1086 H0 Z" />
</clipPath>
<clipPath id="list-piece-upper" clipPathUnits="userSpaceOnUse">
  <path d="M729 0 H1448 V555 L1260 558 L1083 545 L912 559 L750 552 L724 470 L733 340 L719 185 Z" />
</clipPath>
<clipPath id="list-piece-lower" clipPathUnits="userSpaceOnUse">
  <path d="M750 562 L912 569 L1083 555 L1260 568 L1448 565 V1086 H704 L692 842 L709 676 Z" />

```

外轮廓另有 `list-outer-clip`，以接近纸面自然外沿的路径裁去生成图纸外彩边。物理缺失由共用的 `list-physical-missing` SVG `mask` 从纸张与文字**同时挖去**，不是把缺口涂黑。当前两个黑色缺失路径如下；以后即使重做撕口，前后面必须用同一份路径：

<path d="M1101 979 L1124 968 L1147 982 L1173 963 L1194 977 L1219 965 L1247 983 L1271 970 L1295 985 L1321 975 L1343 989 L1354 1086 H1087 Z" fill="black" />

首条挖掉姓名值所在纸区，第二条是底部偏右的独立裁口。纸外背景从洞中露出；侧光、透光、放大镜都不能恢复缺失内容。

## 5. 泥点、侧光和线索位置

- 泥点源图为 `1774×887`，在 1448×1086 的 Canvas 上绘于 `(595,475)`，目标框 `200×100`；图中透明边缘使可见污渍更小。Canvas 只在正面显示。用户选「轻拭泥点」后拖动，54 单位圆头笔刷以 `destination-out` 擦除污渍 alpha；目标框内剩余有效 alpha 像素低于初始的 **30%** 时记录 `list-mud-cleared`。完成状态通过现有云存档结构保存，不保存每一笔轨迹。原图边缘低 alpha 彩点仍要通过纸面 QA，运行时暂做灰阶降饱和。
- 「侧光」工具会用随指针移动的径向 SVG 蒙版展示纸纹，纹理不透明源图的叠加不透明度仅 `.13`。它不圈出正确热点，也不把缺失姓名照出来。
- 名单不再使用通用舞台百分比热点。三处触发区域直接写在纸面 SVG 坐标中，随纸张一起缩放。**拼合、清泥后**才依次开放下一处；玩家直接点击相应文字或裁口便弹出该幕故事卡，不必先选观察工具或按「添加标记」。观察工具只改变纸面观看方式，不是通关钥匙。已读故事可点纸面小勾或右侧手账回看。

| 顺序 | 面／点击对象 | 触发区域 `(x,y,w,h)` | 故事转折 | 保留的未知 |
| --- | --- | --- | --- | --- |
| 01 第三行记录 | 正面／「转三—后随二人」 | `(235,590,740,122)` | 器材、物料之后，第三项写的是人 | 不知二人姓名或后来去向 |
| 02 记号图例 | 背面／两种框形的说明 | `(235,350,800,228)` | 这张纸在第三项停于待交接 | 不等于转送最终失败 |
| 03 回执裁口 | 背面／「回执另存」及裁口 | `(235,665,610,224)` | 后续记录被指向另一页，而这一页没有结局 | 不知另存回执内容或是否仍存 |

三卡齐后，右侧故事手账提供回看，检查台下方直接出现三个故事节点与暂存结论。玩家点击「保存这张纸的故事」，才开放独立「揭开史实档案」入口。这不是判断题的标准答案：它只陈述虚构名单内部可见的事——第三项涉及两位后随者、此页尚记待交接、另有回执提示但内容不明。真实土城史事不能拿来填游戏名单的空白。

## 6. 下一轮精修与验收

1. **P0 实机拼片**：代码已实现 PC 指针拖动和吸附；仍需在不同视口、不同缩放倍率下检查纸片是否易抓取、缝口是否连续、拖动与清泥画布是否互相抢指针。当前未做任意角度旋转，也没有“放手回弹”，不应在玩家文案中承诺。
2. **P0 视觉校准**：清理用户选中的泥点素材红黄边，检查正背纸边共用蒙版后是否露出亮线；确认侧光在不同显示器上不会压低正文对比度。1448×1086 素材仍低于方案里正式 2400×1800 的目标，不承诺 200% 放大完美清晰。
3. **P0 实机文字与触发**：至少在 Windows 常见 PC 浏览器以 100% 与 200% 检查透明手写 PNG 中文是否清晰、符号是否同形、缺口是否真的切断姓名栏。正面三行、背面图例、泥点、三个触发区域与弹卡须逐项截图和操作验收。
4. **P1 剧情与史实边界**：纸件始终标「原创叙事道具／非馆藏原件」；玩家先读完并保存这页纸的故事，之后才由独立入口阅读土城相关史实。游戏里的二人、回执、记号都不冒充真实手迹原文。
5. **P1 素材体积**：五张材质图和十四张透明手写 PNG 现都进入构建，体积明显增加。正式发布前应压缩图片，并复测透明边缘、纸张细纤维与缩放清晰度；不能只为减体积牺牲可读性。

素材和代码集成不改变五件物品的顺序解锁，也不修改其他四件物品的通用检查台。
